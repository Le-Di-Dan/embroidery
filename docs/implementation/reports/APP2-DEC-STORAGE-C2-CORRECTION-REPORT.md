## B. Existing idempotency schema/repository authority

Audited exact source (no inference): `packages/database/src/schema/platform/
idempotency-records.ts`, `packages/persistence/src/platform/idempotency-store.ts`
(+ its integration spec), DB7 contract (`DB7_REPOSITORY_CONTRACTS.md` line 179).

- **Columns:** `id`, `operation_namespace`, `scope_key`, `fingerprint`, `status`,
  `result` (jsonb, **nullable**), `expires_at`, `claimed_at`, `completed_at`,
  timestamps. **Status tuple:** `IN_PROGRESS | COMPLETED` (no FAILED).
- **Arbiter:** unique `(operation_namespace, scope_key)` (CST-048/IDX-058).
- **Mutable** (DB5-A10): `status`, `result`, `expires_at`, `claimed_at`,
  `completed_at`. **Immutable identity:** `operation_namespace`, `scope_key`,
  `fingerprint`.
- **Repository methods:** `claim(namespace, scopeKey, fingerprint)` →
  `claimed | in_progress | replay(result) | conflict`, `complete(result)`
  (gated on `IN_PROGRESS`), `release` (delete of `IN_PROGRESS`), `find`. `claim`
  uses `onConflictDoNothing`; it does **not** write `result` at claim time.
  `complete` is single-shot (`IN_PROGRESS`-gated → no double-complete).
- **IN_PROGRESS result:** the schema permits it (nullable, mutable jsonb); the
  current `claim()` does not populate it. **Fingerprint update:** not permitted
  (immutable identity; mismatch → `IDEMPOTENCY_CONFLICT`, GRD-030).
- **Expiry/reclaim:** `expires_at` + sweeps IDX-093/094; `release` frees an
  `IN_PROGRESS` claim. **Concurrency:** duplicate insert loses on conflict without
  aborting the enclosing transaction (spec-confirmed).

## C. Candidate comparison and selected model

**Selected — I1 (pre-stream durable allocation).** Generate the UUIDv7 `assetId`
+ key, then `claim` `IN_PROGRESS` with `result = {assetId, objectKey}` committed in
its own transaction **before** streaming; a crash-retry recovers the allocation via
`find` and reuses the same identity. Rejected: **I2** (mandatory client checksum) —
needless browser hashing; the fingerprint does not need the content hash, so C1
Option A stands. **I3** (deterministic staging key + `CopyObject` promote) —
avoidable copy/delete and extra orphan windows. **I4** (two-step T2) — no schema
blocker forces reopening it. No hidden fallback: B01 implements I1 only.

## D. Durable asset identity allocation

`assetId` is application-owned UUIDv7 (never storage/filename-derived), generated by
the API before any DB write; the key is derived from it and never an authorization
token. It is durable in the `IN_PROGRESS` `idempotency_records.result` committed
before the object write; a retry reads it back (`claim`→`in_progress`/`replay`, then
`find`), concurrent same-key requests converge on one winner (CST-048), and expired
`IN_PROGRESS` claims are reclaimed with the abandoned object prefix-swept (ADR §4.11).
Persisting the allocation at claim is a **repository implementation gap** (owner
`APP2-B01`: a claim-with-allocation write on `IdempotencyStore`), **not** a schema gap.

## E. Canonical fingerprint and mismatch semantics

`fingerprint = sha256(canonical, key-sorted JSON)` over **pre-stream** identity
only: `{version, operation_namespace, admin/account scope, idempotency key, asset
kind, classification, normalized declared MIME, normalized declared filename}`.
Deterministic, bounded, PII-minimized, immutable, safe to log only as its hash;
**excludes** raw file bytes, content SHA-256, raw filename where avoidable, session
cookie, request id, multipart boundary, ETag. Same key + different fingerprint →
`IDEMPOTENCY_CONFLICT` (no second object accepted, no prior result leaked beyond the
authorized safe replay); the public `409`-class error name is routed to `APP2-B01`
in the canonical taxonomy, not invented here.

## F. Concurrency/crash matrix

Locked in ADR §4.2e (winner/loser · object writes · asset identity · HTTP
category) for: same key+fp first `IN_PROGRESS`; same key+fp first `COMPLETED`
(replay, 0 upload); same key different fp (conflict, 0 object); same key after
failed/expired claim (reclaim then claim); two first requests racing (one winner,
CST-048); retry after object done before Tx A (recover, overwrite same key);
retry after Tx A before Tx B (replay, resume from truthful `UPLOADED`); retry after
Tx B before HTTP response (replay). Target: **at-least-once attempt / idempotent
durable effect / one accepted asset identity** — explicitly **not** exactly-once.
Crash-window invariants **CW-01…CW-07** proven (ADR §4.2e).
