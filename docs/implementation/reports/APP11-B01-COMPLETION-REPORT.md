## E. Domain semantics

**`create = DRAFT`.** The create DTO does not declare `status`, and every DTO is
`.strict()`, so a body naming it is a **400 refusal**, not a silently dropped
field. The repository writes the literal `'DRAFT'`. Proved twice: the DTO spec
rejects `{ status: 'PUBLISHED' }`, and the HTTP suite reads back
`status === 'DRAFT'` from the 201 body.

**PATCH cannot change slug, status or assets.** None of the three is declared on
`UpdateGalleryEntryBody`, and none has an argument on
`UpdateGalleryEntryFields` or `updateAuthoring` — so each is *unrepresentable*
rather than merely unimplemented. `.strict()` turns each into a 400, and the
HTTP suite re-reads the entry after every refusal to prove `slug` and `status`
did not move. `archivedAt` and `altText` are refused the same way.

**Linked-product validation.** `LinkedProductResolver` calls the existing
internal `CATALOG_SUBJECT_PORT.findProductLabels` — no second Product
repository, no HTTP call to our own API, no catalog table read from Gallery
(`BACKEND_CONVENTIONS.md` §10). Publication state is deliberately **not** a
predicate: an operator links a product they are still preparing, and public
projection safety is `APP11-B03`'s. `undefined` and `null` both name no product
and are not looked up, so clearing a link cannot fail because the old product is
gone. Validated before the write on both create and patch — the HTTP suite
proves a rejected patch leaves the stored title untouched.

**No per-image alt text.**

```text
PER_IMAGE_ALT_DB_FIELD     = false
PER_IMAGE_ALT_API_FIELD    = false
PER_IMAGE_ALT_ADMIN_EDITOR = false
```

Asserted structurally against the committed OpenAPI document: every schema whose
name matches `/Gallery/i` is serialised and matched against `/alt[_ ]?text/i`,
which must not hit. `altText` is also a rejected input on both create and patch.

**No publication and no asset mutation.** `changeStatus` and `attachAsset` exist
on the AGG-18 repository and are `APP11-B02`'s. The contract spec strips comments
from the B01 controller and service and asserts neither name appears in code —
so a call added later fails by name rather than escaping as untested behaviour.
The published surface is asserted to contain no `.../assets`, `.../publication`,
`/api/public/gallery-entries*` or `/api/admin/content-pages` path.

## F. Repository delta

The existing `GalleryEntryRepository` was **extended, not rewritten**. Nothing
existing was removed or re-signed; `create`, `attachAsset`, `changeStatus`,
`findBySlug`, `findById` and `listAssetIds` keep their contracts.

| Added | Why B01 needs it |
|---|---|
| `AdminGalleryEntry` type | The narrow `GalleryEntry` carries no `displayOrder`, SEO, `isIndexable`, `archivedAt` or timestamps. A second type rather than a widened one, so existing consumers do not start compiling against columns they have no use for. |
| `findAuthoringById` | The Admin detail read, and the create read-back. |
| `listAuthoring` | The keyset page — `display_order ASC, id ASC`, fetching `limit + 1`. |
| `updateAuthoring` | Partial field update. No argument reaches `status` or `archived_at`. |
| `listAssetLinks` | Ordered associations for the detail read. |
| `summarizeAssets` | Cover + count for a whole page in one statement (no N+1). |

Two existing seams were touched minimally:

- `CreateGalleryEntryInput` gained optional `seoTitle`, `seoDescription` and
  `isIndexable`. The adapter previously hard-coded `isIndexable: true`; it now
  reads `input.isIndexable ?? true`, so every existing caller behaves exactly as
  before. Proved by the untouched `content-persistence` integration suite.
- The row mapper moved to `gallery-entry-row.mapper.ts` so the adapter stays
  inside the review threshold (294 lines) with both projections side by side.

**Ordering choice, stated.** The Admin list is *not* `IDX-066`'s order. That
index is the published public listing and its partial predicate excludes DRAFT
and ARCHIVED — exactly the rows an operator opens the Admin list to find. The
sort key `(display_order, id)` is the same pair `IDX-066` uses, so the two
surfaces present entries in the same relative order.

**Concurrency, stated as a decision.** `adminGalleryEntry_update` carries **no**
`expectedUpdatedAt` token. The prompt's §6.3 enumerates the patch contract with
no token, and the repository has an established precedent for a token-free
authoring PATCH on a small aggregate — `adminSku_update` (`APP7-B01`). The
guarded-write precedent (`adminProduct_update`) exists because a product patch
races a *lifecycle* transition; a gallery entry's lifecycle is `APP11-B02`'s and
unreachable from here. `updated_at` is still advanced on every patch, so the
token exists in the response for `APP11-B02` to adopt if it needs one. Recorded
as follow-up `FU-APP11-B01-01`.

  Two entries may share a position; the `(display_order, id)` tie-breaker keeps
  paging deterministic, but the Admin list UI (`APP11-A01`) may want a
  re-ordering affordance rather than a free integer field.

  the generated client but are not on the `@embroidery/api-client` public
  boundary, by the package's consumer-driven release rule. `APP11-A01`/`A02`
