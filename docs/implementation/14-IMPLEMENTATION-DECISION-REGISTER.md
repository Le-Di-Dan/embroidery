| IMP-D026 | The 2D Design Studio renderer is **native SVG rendered by React 19 itself** — APP3 adds **no** rendering-engine dependency (no Konva, no Fabric, no PixiJS) and **no** interaction library (the platform Pointer Events API replaces the stale `interactjs 1.10.27`). **Architecture (mandatory even with one renderer):** the engine-neutral design document owned by `packages/design-document` (RFC 8785 JCS + SHA-256, ADR-DB1-012) is the single source of truth and the renderer is a pure projection of it; all rendering is reached through one narrow **renderer-adapter** contract (mount/load/select/transform/z-order/lock/hide/group/viewport/hit-test/serialize/destroy); engine-native serialization (`toJSON()`/`toObject()`) is never persisted or transported; selection, hover, handles, viewport zoom/pan and the watermark are runtime state and are never serialized; mutable runtime objects never enter Zustand or React state; geometry and pixel↔millimetre conversion live in `packages/design-engine`; undo/redo is a domain command/snapshot concern, never an engine history stack; transform handles are **DOM** elements outside the element box at ≥44 px and focusable; the Studio is client-only and lazily loaded behind a server-rendered route shell. **Watermark:** preview policy supplied at mount/load, non-selectable, non-deletable, topmost, regenerated on load, opaque session marker with no raw PII, never document content, never claimed as screenshot prevention (D-008/D-009). **Assets:** elements reference an asset id + approved derivative; no monotonic heap growth over 20 mount/destroy cycles. **Rejected:** Fabric.js `7.4.0` (single-canvas full repaint fails the frozen budgets at product scale — desktop transform p95 33.4–42 ms, mobile 50.1 ms, long tasks to 179–203 ms — and attribution shows the *mandatory* repeated watermark is a dominant part of that cost; ## 3. Decision procedure

For an open consequential decision:

1. Audit existing repository ADRs and implementation.
2. Compare options against locked product/architecture constraints.
3. Run a bounded spike only when evidence is required.
4. Create or update an ADR.
5. Record the decision here or link the authoritative ADR.
6. Only then unblock dependent checkpoints.

Do not use a checkpoint implementation as an implicit ADR.
